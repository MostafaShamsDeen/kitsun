# Kitsun

All your AIs in one window (formerly **Multi Claude**). For now every tab is a Claude account: each tab runs the real Claude desktop app (chat, Code, Cowork, projects, connectors), signed in to its own account, so every account's usage stays separate. All tabs keep running while you switch, and the layout button shows two or three side by side. More kinds of tab (desktop apps, websites, terminals) are on the way; each tab already has a `kind` in `profiles.json`.

**Taking over from Multi Claude.** The first time Kitsun starts it copies `%APPDATA%\Multi Claude\profiles.json` and `stats-cache.json` into `%APPDATA%\Kitsun` (the old folder is left as it was). A running Multi Claude is asked to quit (`--quit`) before anything is docked, since two apps docking the same Claude windows would fight over them. The installed copy also replaces the old login item (keeping the setting) and removes the old Start Menu shortcut.

## How it works

- The **main** account is your normal Claude app, with its usual data folder.
- Every other account is the same Claude app started with `--user-data-dir=%LOCALAPPDATA%\Claude-Profiles\<id>`, so it has its own sign-in, settings and local sessions. The Claude app supports this; its log says `stay_chosen_folder`.
- Each Claude window is docked inside Kitsun as a child window (`lib/win32.js`, via `koffi`). Chromium only paints inside another program's window with DirectComposition off, so Kitsun starts every copy with `--disable-direct-composition`. A copy that was started some other way shows a "bring it in here" notice instead.
- Claude Code in each copy uses your usual `~/.claude` folder (settings, memory, past sessions) unless "Share Claude Code settings" is turned off for that account. Then it gets `CLAUDE_CONFIG_DIR=%USERPROFILE%\.claude-accounts\<id>`. Usage is billed to each window's own account either way.
- The close button hides Kitsun to the tray by default, with every Claude window still docked and running. Quitting it (tray menu → Quit) hands the Claude windows back hidden. They keep running like a Claude window closed to the tray, and reopening Kitsun docks them again.

## Using it

- Click a tab to switch. **Ctrl+Alt+1–9** also switches, even while typing in Claude.
- Click the logo (top left), or press **Ctrl+Alt+0**, for the home screen: every account's plan usage, sessions, prompts and output tokens, memory and uptime, plus activity charts. The numbers come from files already on this PC (`lib/stats.js`): each copy's `plan-usage-history.json` and local Code sessions, and the Claude Code transcripts in `~/.claude/projects`. Transcripts are read once in the background and remembered in `stats-cache.json`, so later visits only read new messages.
- **Search and switch:** press **Ctrl+Alt+K** (or the search button in the title bar, the search box on Home, or the tray's **Search…**). It lists the accounts, Home, Settings, Manage accounts, split view and Start / Stop for each account, plus your Claude Code sessions in every account as you type. Sessions match on their title, earlier titles, project folder, Claude's summary of the last turn, model and first prompt (`lib/search.js`, read-only from each copy's session files and the start of each transcript). ↑ ↓ and Enter, or the mouse; Esc closes. Opening a session shows its account and asks that account's Claude to open it (`claude://code/continue?session=…`, sent only to that account's own copy). An archived session only shows its account; pick it from Claude's sidebar.
- **Continue in another account (beta):** when one account is out of usage, carry a Claude Code session on in another. Each recent session on a Home card has a small arrow button (at its right), and the switcher has **Continue in…** on the chosen session (or **Ctrl+Enter**); pick the account (its usage is shown; the one with the most left is marked), confirm, and Kitsun makes a **new** session there that starts from a copy of the conversation (`lib/handoff.js`). The original is never changed; the two don't sync afterwards. It works like Claude's own fork: the transcript is copied to a new id in the same `~/.claude/projects` folder (with its Remote Control link cleared), and the new session file holds only what Claude's own import keeps (folder, title, times), so the other account uses its own model, permission mode and connectors. Only accounts that share your Claude Code folder can take a session. A running Claude reads its sessions only when it starts, so Kitsun offers to restart that account (a clean quit, as Stop does) and opens the session; one that isn't running just starts with it open. Sessions in a Git worktree, over SSH/WSL, or mid-turn (working, or waiting on a permission, question or plan prompt; read from the transcript itself) can't be continued yet; one cut off mid-turn by a quit or crash can. The new session goes in the target account's org folder that has its sessions (the plan-usage org only if that folder is there); an account that never opened its Code tab is refused.
- **Chrome per account:** each Home card has a **Chrome: <profile>** button that opens the Chrome profile whose Claude in Chrome extension is signed in to that account (also in the switcher, "Open Chrome for …", and the tray's **Open Chrome** submenu). Kitsun finds it read-only (`lib/chrome.js`): Chrome's `Local State` lists the profiles, and each profile's extension storage (a LevelDB) holds the signed-in account's ID, matched against the account's own `config.json`; the newest record wins, so an old sign-in left in the database doesn't count. To pick a profile yourself, choose it under **Chrome profile** in the account's settings (Automatic is the default). Chrome is started as `chrome.exe --profile-directory=<profile>`.
- **Layouts:** the layout button (top right, next to search) opens a menu: **Single**, **Side by side** (two accounts) or **Three columns** (needs three accounts; also in the switcher). A tab click, or **Ctrl+Alt+1–9**, fills the active pane (the one with the coloured border; clicking into a Claude window makes its pane active), and the tabs show which pane each account is in (1, 2, 3). Drag the strip between two panes to resize them (no pane gets narrower than about 360 px); double-click it for equal widths. Fewer panes keep the active account on screen, and the others come back when you switch to more panes again. The layout and divider positions are saved in `profiles.json` under `ui` (`layout`, `panes`, `splitRatio`, `tripleRatios`).
- Click **+** to add an account. Right-click a tab, or use the gear, to rename, recolour or remove one.
- The sliders button (next to the gear) opens **Settings**: start with Windows, start in the tray, close to the tray, restart accounts that quit, and notifications. Settings are saved in `profiles.json` under `settings`.
- **Accounts that close by themselves come back.** When a copy Kitsun didn't stop goes away, its own `main.log` says why (`lib/health.js`), and its tab says so. Windows closes every copy to install a Claude update ("close-app"); those are reopened once the update is in, and a crash is reopened after ~5 s, at most 3 times in 10 minutes. A copy you quit from Claude's menu, or that Windows closed while signing out or shutting down, is left closed. Turn this off in Settings.
- After a Claude update, a note says so ("Claude updated to 4.4212 · reopened Personal and Studio"); with the window hidden or in the background it is also a Windows notification (Settings → Notifications).
- **Needs you:** a tab shows a number when Claude Code sessions in that account are waiting for you (a permission or question prompt, a plan to approve, or a turn that ended asking you something), and a dot when a turn finished while you were elsewhere. Home lists the waiting sessions at the top ("Needs you"; click one to show its account) and each account card counts them. When a session in an account you aren't looking at starts waiting, a toast says so (with **Show**), and Windows does too while Kitsun isn't in front; once per waiting period. It comes from each copy's own files (`lib/attention.js`, polled every 5 s): live prompts from its `main.log`, the rest from its local session files and the Code transcripts. Showing an account counts as having seen what it shows.
- **Plan limits:** the ring around each tab's dot is that account's 5-hour usage; hover the tab for "Work · 5-hour 64% · weekly 71%". When an account reaches 90% of its 5-hour (or weekly) limit, a toast names the account with the most left and offers **Switch**; another one says when the 5-hour limit has reset. Both kinds of notice can be turned off in Settings → Notifications.
- **Not responding:** a Claude window that hasn't responded for 20 s gets a red dot on its tab and a "isn't responding" alert in the title bar with **Wait** (ask again in a minute) and **Restart**. Restart ends that copy and everything it runs (taskkill /T /F; for the main account, that includes any Claude Code session in it) after a Windows confirmation, then starts it again.
- **Stop** (in an account's settings, or the tray menu's Stop submenu) asks that Claude to quit cleanly, as Windows does before an update. If it is still running after 20 s, or has no window to ask (or isn't responding), you can force it. Stop on a frozen account asks in a Windows confirmation (a page dialog would sit under the frozen window), and while a frozen window is on screen the switcher, Settings and other dialogs stay closed and say to use Wait or Restart. A stopped account stays closed, also on a tab click, until you press Start or reopen Kitsun.
- The tray icon (by the clock) shows the window on a click. Its menu opens Home or any account, starts every stopped account, stops one, opens Settings, and is where you **Quit Kitsun** while "Close to the tray" is on. If a hidden account's Claude asks for attention (e.g. you click one of its notifications), Kitsun comes back showing that account.
- **Start with Windows** (only the installed copy in `%LOCALAPPDATA%\Programs\Kitsun`; an entry left by another copy, e.g. the dist build, is pointed back at it or removed) adds a Windows login item that starts Kitsun with `--hidden`: every account starts, and the window waits in the tray. Turning it off in Task Manager's Startup apps also turns the setting off.
- Signing in a new account: choose **Continue with email** in its tab and type the code from the email. Don't click the email's button, because Windows would send it to your main Claude window. If the email has no code, paste its link under "Finish signing in with a link" in that account's settings.
- To bring your main Claude app into its tab the first time, quit it once (≡ menu → File → Exit). Kitsun then reopens it inside.

## Develop / rebuild

```bash
npm start            # run from source
npm run package      # build dist/Kitsun-win32-x64
```

The installed copy is `%LOCALAPPDATA%\Programs\Kitsun`. Close Kitsun, then mirror the new `dist\Kitsun-win32-x64` folder over it. Settings live in `%APPDATA%\Kitsun\profiles.json`.

A shell inside a Claude Code session runs in the Claude app's sandbox: its writes to `%APPDATA%` and `%LOCALAPPDATA%` land in the Claude package's `LocalCache` folder instead. Kitsun spots this at startup and relaunches itself through Explorer, so its settings stay in the real folder. Scripts that read or change those settings, or swap builds, should run through Task Scheduler.

To look at the home screen in a normal browser with sample data, serve the project folder (for example `py -m http.server 5178`) and open `/scripts/home-preview/`. Add `?state=empty` or `?state=one` for the edge cases, `&dialog=settings` (with `&dev=1` for a run from source) to open Settings, and `&tabs=8&hint=1` to check a crowded title bar. `&show=<id>` shows an account instead of home, with `&layout=split|triple` (or `&split=1`) for two or three panes, `&focus=N` (0-based) for the active pane, and `&ratio=0.3` or `&ratios=0.5,0.3,0.2` for the dividers; `&menu=layout` opens the layout menu, `&drag=<k>:<dx>` drags divider k by dx px (`:hold` keeps it held), `&dblclick=<k>` double-clicks it, and `?state=two` has two accounts (Three columns disabled); `&health=1` makes Personal frozen and Studio closed for an update; `&exit=update|update-off|crash|gaveup|user|shutdown|stopped` picks how Studio closed; `&reopening=1` and `&stopping=1` show those spinners; `&dialog=account` or `&dialog=stop` open Personal's account dialog or Stop confirmation (`&stuck=1`: it won't quit; `&stuck=noask`: it couldn't be asked); `&notice=update|frozen|reopened|needs|limit|reset` shows that toast (`needs` and `limit` have a button). Sample "needs you" data is on by default; `&needs=0` turns it off and `&needs=unseen` shows only finished-unseen dots. `&switcher=<text>` opens the quick switcher with that text typed (`&switcher=` for empty), `&move=N` presses ↓ N times, and `&searchdelay=<ms>` slows the sample search to show "Searching…". `&chrome=0|unlinked|manual|missing` sets the sample Chrome profiles (no Chrome; Studio not linked; Personal picked one by hand; Personal's pick is gone), `&dialog=account&for=Studio` opens another account's dialog, and `&openchrome=<id>` presses that card's Chrome button. `&handoff=menu|confirm|restart|done` walks through Continue in… from Work's first recent session (`&from=<id>` for another card, `&to=<name>` for the target; `&tabs=1&to=Client` for a stopped one), and `&handoff=switcher` presses Ctrl+Enter in the switcher.

`lib/health.js` has no Electron in it: `classifyQuit(text)` takes the tail of a `main.log`, so it can be checked against real logs with plain `node`. Neither has `lib/attention.js`: `createAttention().poll(accounts, { running })` reads the real accounts read-only, and its header lists the evidence behind each "needs you" rule. `lib/search.js` is the same: `createSearch().query(accounts, 'text')` searches the real accounts read-only. So is `lib/chrome.js`: `createChrome().snapshot(accounts)` shows which Chrome profile each account links to, and its header explains the rule. `lib/handoff.js` too: `continueSession({ sessionId, source, target })` takes the folders explicitly, so it can be run against a copied folder tree; its header lists what Claude's own fork and import do, which it follows.

`KITSUN_EVAL=<file.js>` (dev only) runs a script in the window after startup, which is useful for testing without clicking.
